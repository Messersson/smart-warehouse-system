# 仓库系统项目大纲

## 一、项目概述

本项目是一个面向仓储业务的 WMS 仓库管理系统，覆盖基础资料、入库、出库、库存、盘点、预警、审批、异常工单、计费结算、权限管理以及移动端扫码作业等核心业务。系统以 Web 管理端为主，同时提供安卓手持扫码枪 App，适合仓库后台管理人员、仓库作业人员、主管审批人员和运维人员共同使用。

项目目标：

- 建立仓库、库位、货主、供应商、客户、商品等基础数据体系。
- 支持入库收货、上架、出库拣货、发运、库存查询和库存流水追踪。
- 支持驿站、外卖柜、校园取件等带取件场景的入库与滞留管理。
- 支持 PDA/手持扫码枪对入库单、出库单、库位、商品条码进行快速识别、记录留存和现场操作。
- 支持盘点、库存调整、预警扫描、异常工单和审批流。
- 支持按合同规则生成客户计费账单。
- 支持基于角色和菜单的登录鉴权与权限控制。

## 二、技术架构

### 1. 后端服务

- 技术栈：Java 17、Spring Boot、Spring Data JPA。
- 目录：`backend/`。
- 职责：提供 REST API、业务规则处理、数据持久化、登录鉴权、权限校验、预警定时扫描和统一异常响应。
- 主要分层：
  - `controller`：接口入口，负责接收前端和移动端请求。
  - `service`：业务逻辑层，处理入库、出库、库存、盘点、预警等核心流程。
  - `repository`：数据访问层，基于 JPA 操作数据库。
  - `entity`：数据库实体模型。
  - `dto`：接口请求和响应对象。
  - `security`：token、密码、登录用户上下文和 API 鉴权拦截。
  - `config`：跨域、请求 ID、JSON、Web MVC 和数据库结构补丁配置。

### 2. 前端管理端

- 技术栈：Vue 2.7、Element UI、Vite。
- 目录：`frontend/`。
- 职责：提供后台管理页面，包括驾驶舱、基础资料、入库、出库、库存、预警、权限、盘点、计费、审批、异常工单等页面。
- 主要页面：
  - 登录与注册页面。
  - 主布局与菜单导航。
  - 驾驶舱页面。
  - 基础资料通用维护页面。
  - 入库、出库、库存、PDA 扫码、驿站入库页面。
  - 预警、权限、盘点、计费、审批、异常工单页面。

### 3. 安卓手持扫码端

- 技术栈：Android、Kotlin、Gradle。
- 目录：`handheldbarcodescanner/`。
- 职责：为仓库现场作业提供扫码登录、扫码识别、收货、上架、取件、拣货、发运、盘点和库存查询能力。
- 支持配置服务地址，适配本地 Docker、局域网服务器和正式 HTTPS 服务器。

### 4. 数据库与部署

- 数据库：MySQL 8。
- 初始化脚本：`deploy/mysql/warehouse_system.sql`。
- 容器编排：`docker-compose.yml`，包含 MySQL、后端、前端三个服务。
- 默认访问端口：
  - 前端：`80`
  - 后端：`18080`
  - MySQL：`3307`

## 三、用户与权限体系

### 1. 登录模块

功能说明：

- 用户通过账号和密码登录系统。
- 登录成功后后端生成 token，前端保存用户信息和可访问菜单路径。
- 后续接口请求统一携带 `Authorization: Bearer <token>`。
- 后端对 `/api/**` 接口进行统一鉴权，未登录用户不能访问业务接口。

主要能力：

- 用户名密码校验。
- token 生成与过期控制。
- 登录时间记录。
- 历史明文密码兼容和自动升级为 PBKDF2 哈希密码。

### 2. 注册模块

功能说明：

- 新用户可以通过注册页提交账号申请。
- 注册后默认赋予系统配置的角色和状态。
- 如果默认状态为 `PENDING`，需要管理员在权限管理中启用后才能登录。

主要能力：

- 用户名唯一性校验。
- 注册信息保存。
- 默认角色分配。
- 注册结果提示。

### 3. 权限管理模块

功能说明：

- 管理系统用户、角色、菜单和角色菜单授权关系。
- 系统根据角色拥有的菜单路径控制前端菜单显示和后端接口访问。

主要功能：

- 用户管理：新增、编辑用户，维护用户名、显示名称、手机号、邮箱、角色、状态和备注。
- 角色管理：新增、编辑角色，维护角色编码、角色名称、角色描述和状态。
- 菜单管理：维护菜单编码、菜单名称、菜单路径、组件名称、图标、排序、可见状态。
- 角色授权：为角色分配可访问菜单。
- RBAC 校验：后端根据角色菜单路径判断用户是否有权限访问对应接口。

## 四、核心功能模块

### 1. 首页驾驶舱模块

功能说明：

首页驾驶舱用于展示仓库运营概况，帮助管理人员快速掌握当前系统运行状态和待处理事项。

主要功能：

- 统计仓库数量、商品数量。
- 统计待处理入库单数量。
- 统计待处理出库单数量。
- 统计未处理预警数量。
- 统计当前库存总量。
- 展示最近入库单。
- 展示最近出库单。
- 展示最新高频预警。

对应页面：

- `/dashboard`

对应接口：

- `GET /api/dashboard/overview`

### 2. 基础资料管理模块

基础资料是仓库业务运行的前提，主要维护仓储作业中反复使用的基础档案。

#### 2.1 仓库管理

功能说明：

- 维护仓库基础信息和业务场景配置。
- 支持普通仓、冷链仓、保税仓等仓库类型。
- 支持通用仓储、驿站、外卖柜、校园取件等场景。
- 支持配置滞留预警时长、短信提醒、自动分配库位和扫码模式。

主要字段：

- 仓库编码、仓库名称、仓库类型、业务场景。
- 联系人、联系电话、省市区、详细地址。
- 滞留时长、短信提醒开关、短信重发间隔。
- 自动分配库位、扫码模式、状态、备注。

#### 2.2 库位管理

功能说明：

- 管理仓库下的具体库位。
- 支持库区、通道、货架、层、位等库位结构。
- 支持容量、已用量、是否可拣选和状态管理。

主要字段：

- 所属仓库、库区、库位编码、库位名称。
- 通道、货架、层、位。
- 容量、已用量、是否可拣选、状态、备注。

#### 2.3 货主管理

功能说明：

- 管理库存归属方。
- 支持自营和第三方货主。

主要字段：

- 货主编码、货主名称、货主类型。
- 联系人、联系电话、邮箱、地址、状态、备注。

#### 2.4 供应商管理

功能说明：

- 管理入库来源供应商。
- 入库单可关联供应商信息。

主要字段：

- 供应商编码、供应商名称。
- 联系人、联系电话、邮箱、地址、状态、备注。

#### 2.5 客户管理

功能说明：

- 管理出库客户和取件客户信息。
- 出库单、入库取件场景和计费合同可关联客户。

主要字段：

- 客户编码、客户名称、客户类型。
- 联系人、联系电话、邮箱、地址、状态、备注。

#### 2.6 商品管理

功能说明：

- 维护 SKU 商品资料，是入库、出库、库存、盘点和扫码识别的核心基础数据。
- 支持条码、批次、序列号、安全库存、保质期等信息。
- 商品条码留空时系统自动生成条形码，并支持生成可打印标签用于粘贴到货物上。

主要字段：

- SKU 编码、商品名称、规格、分类、品牌、单位、条码。
- 安全库存、最大库存、保质期天数。
- 是否启用批次、是否启用序列号。
- 重量、体积、销售价格、状态、备注。

对应页面：

- `/master/warehouses`
- `/master/locations`
- `/master/owners`
- `/master/suppliers`
- `/master/customers`
- `/master/products`

对应接口：

- `/api/warehouses`
- `/api/locations`
- `/api/owners`
- `/api/suppliers`
- `/api/customers`
- `/api/products`
- `/api/lookups`

### 3. 入库管理模块

功能说明：

入库管理负责处理商品从外部进入仓库的全过程，包括创建入库单、收货、上架、库存增加、库位占用更新和库存流水记录。

主要功能：

- 入库单列表查询。
- 入库单详情查看。
- 新建入库单。
- 维护入库明细，包括商品、批次、生产日期、到期日期、预计数量、实际数量、合格数量和目标库位。
- 入库收货，记录实际到货和收货时间。
- 入库上架，将合格数量写入库存。
- 自动分配库位，根据仓库配置和库位剩余容量选择可用库位。
- 生成库存流水，记录入库前数量、变动数量和入库后数量。
- 对驿站、外卖柜、校园取件等场景使用统一作业编码并生成取件截止时间。

业务状态：

- `CREATED`：入库单已创建。
- `RECEIVED`：已收货。
- `PUTAWAY_COMPLETED`：已上架。

取件状态：

- `NOT_REQUIRED`：不需要取件。
- `WAITING_PUTAWAY`：等待上架后进入取件状态。
- `PENDING_PICKUP`：待客户取件。
- `NOTICE_SENT`：已发送滞留提醒。
- `DELAY_REQUESTED`：客户申请延迟。
- `PICKED_UP`：客户已取件。
- `REFUSED`：客户拒收。

对应页面：

- `/inbounds`
- `/station-inbound`

对应接口：

- `GET /api/inbounds`
- `GET /api/inbounds/{id}`
- `POST /api/inbounds`
- `POST /api/inbounds/{id}/receive`
- `POST /api/inbounds/{id}/putaway`
- `POST /api/inbounds/{id}/pickup-action`

### 4. 驿站入库与取件模块

功能说明：

该模块面向驿站、外卖柜、校园取件等业务场景，对普通入库流程进行扩展，增加收件人、手机号、统一作业编码、滞留时间、短信提醒和客户取件动作。

主要功能：

- 支持入库单绑定客户或收件人信息。
- 支持生成统一作业编码，入库、出库和扫码作业使用同一套编码规则。
- 支持设置取件截止时间。
- 支持客户取件完成后扣减对应库存。
- 支持客户延迟取件，自动延长截止时间并生成异常工单。
- 支持客户拒收，标记拒收状态并生成高优先级异常工单。
- 支持滞留超时后生成预警、异常工单和短信提醒队列。

适用场景：

- 快递驿站暂存。
- 外卖柜寄存。
- 校园取件点。
- 其他需要客户自提的临时仓储场景。

### 5. 出库管理模块

功能说明：

出库管理负责商品从仓库发出的全过程，包括创建出库单、拣货完成、发运、库存扣减、库位占用释放和库存流水记录。

主要功能：

- 出库单列表查询。
- 出库单详情查看。
- 新建出库单。
- 维护出库明细，包括商品、批次、计划数量、已扫数量、库位。
- 支持客户、货主、承运商、业务来源单号、优先级和计划发运时间。
- 拣货完成，更新出库单作业状态。
- 发运前必须逐件扫描商品条码、SKU 或二维码内容，所有明细达到计划数量后才能完成出库并扣减库存。
- 库存不足时阻止出库并返回业务异常。
- 生成出库库存流水。

业务状态：

- `CREATED`：出库单已创建。
- `PICKING_COMPLETED`：拣货完成。
- `SHIPPED`：已发运。

对应页面：

- `/outbounds`

对应接口：

- `GET /api/outbounds`
- `GET /api/outbounds/{id}`
- `POST /api/outbounds`
- `POST /api/outbounds/{id}/picking`
- `POST /api/outbounds/{id}/ship`

### 6. 库存管理模块

功能说明：

库存管理用于查询当前仓库库存，跟踪商品在不同仓库、库位、货主和批次下的库存数量。

主要功能：

- 实时库存查询。
- 按关键字搜索 SKU、商品名称、商品条码、批次号、库位编码。
- 按仓库筛选库存。
- 展示库存总量、锁定数量、可用数量。
- 展示最后入库时间、最后出库时间和最后变动时间。
- 入库、出库、客户取件、盘点调整时自动维护库存。
- 自动维护库位已用容量。
- 记录库存流水，便于追溯库存变化来源。

对应页面：

- `/stocks`

对应接口：

- `GET /api/stocks`

相关数据表：

- `inventory_stock`
- `inventory_movement`

### 7. PDA 扫码模块

功能说明：

PDA 扫码模块用于仓库现场快速识别业务对象，并根据对象类型执行对应作业。系统同时提供 Web 端 PDA 页面和安卓手持扫码枪 App。

扫码可识别对象：

- 入库作业编码。
- 出库作业编码。
- 库位编码。
- 商品 SKU 编码。
- 商品条码。

主要功能：

- 扫码查询对象信息。
- 支持二维码、条形码、Data Matrix、PDF417、Aztec 等扫码格式的原始内容留存。
- 支持解析普通文本、JSON、URL 参数、键值文本和 GS1 编码中的业务编码。
- 扫码后自动保存扫码格式、原始内容、解析编码、匹配对象、设备来源和操作人。
- 扫入库单后可进行收货、上架、取件完成、延迟取件、拒收等操作。
- 扫出库单后可继续扫描商品条码、SKU 或二维码内容确认出库数量，全部确认后完成发运。
- 扫库位后可查看库位所属仓库、库区和状态。
- 扫商品后可查看商品基础信息和当前库存分布。
- 安卓端支持最近扫码记录本机保存，便于重复查询。

对应页面：

- `/pda`

对应接口：

- `GET /api/scan/lookup`
- `GET /api/scan/records`
- `POST /api/scan/records`

相关数据表：

- `scan_record`

安卓端目录：

- `handheldbarcodescanner/`

### 8. 盘点管理模块

功能说明：

盘点管理用于核对系统库存和实际库存是否一致，并对差异进行处理。系统支持按仓库和货主生成盘点单，盘点完成后可生成异常工单，并支持库存调整。

主要功能：

- 创建盘点单。
- 根据当前库存自动生成盘点明细。
- 查询盘点单列表和详情。
- 录入实盘数量。
- 自动计算账面数量、实盘数量和差异数量。
- 无差异时盘点单可直接完成。
- 有差异时进入待复核状态，并自动生成异常工单。
- 支持根据实盘结果进行库存调整。
- 调整后生成盘点调整库存流水。
- 同步更新库位占用量。

业务状态：

- `CREATED`：盘点单已创建。
- `COUNTING`：盘点中。
- `FINISHED`：盘点完成且无差异。
- `REVIEW_REQUIRED`：存在差异，需复核。
- `ADJUSTED`：已完成库存调整。

对应页面：

- `/stock-takes`

对应接口：

- `GET /api/stock-takes`
- `GET /api/stock-takes/{id}`
- `POST /api/stock-takes`
- `POST /api/stock-takes/{id}/count`
- `POST /api/stock-takes/{id}/finish`
- `POST /api/stock-takes/{id}/adjust`

### 9. 预警中心模块

功能说明：

预警中心用于监控仓库业务异常和超时情况。系统支持根据预警规则定时扫描业务数据，并生成预警事件。

主要功能：

- 预警列表查询。
- 手动触发预警扫描。
- 定时自动扫描预警。
- 预警确认处理。
- 自动关闭已恢复正常的预警。
- 取件滞留超时时自动生成异常工单。
- 配置短信提醒后可生成短信通知队列。

当前支持的预警类型：

- 入库未收货超时。
- 入库收货后未上架超时。
- 出库未按计划发运超时。
- 呆滞库存预警。
- 客户取件滞留超时预警。

预警状态：

- `OPEN`：待处理。
- `ACKNOWLEDGED`：已确认。
- `RESOLVED`：已恢复。

对应页面：

- `/alerts`

对应接口：

- `GET /api/alerts`
- `POST /api/alerts/scan`
- `POST /api/alerts/{id}/ack`

相关数据表：

- `alert_rule`
- `alert_event`

### 10. 通知消息模块

功能说明：

通知消息模块用于保存系统需要发送的通知记录，目前主要用于客户取件滞留短信提醒。

主要功能：

- 生成短信提醒队列。
- 记录接收人姓名和手机号。
- 记录通知标题和内容。
- 记录发送状态和响应状态。
- 支持查询通知消息列表。

对应接口：

- `GET /api/notifications`

相关数据表：

- `notification_message`

### 11. 异常工单模块

功能说明：

异常工单用于沉淀业务异常处理过程。系统既支持人工创建异常工单，也支持盘点差异、取件滞留、客户拒收、客户延迟等业务自动生成异常工单。

主要功能：

- 异常工单列表查询。
- 手动创建异常工单。
- 工单指派处理人。
- 工单处理完成。
- 工单关闭。
- 记录关联业务类型、业务 ID、业务单号。
- 记录严重程度、状态、报告人、处理人和审批状态。

工单状态：

- `OPEN`：待处理。
- `IN_PROGRESS`：处理中。
- `RESOLVED`：已解决。
- `CLOSED`：已关闭。

对应页面：

- `/exceptions`

## 五、主要业务流程

### 1. 入库业务流程

1. 管理员或仓库人员创建入库单。
2. 系统保存入库单和入库明细。
3. 仓库人员执行收货，入库单状态变为已收货。
4. 仓库人员执行上架。
5. 系统根据明细合格数量增加库存。
6. 系统更新库位已用容量。
7. 系统记录库存流水。
8. 如果是取件场景，系统生成待取件状态和取件截止时间。

### 2. 出库业务流程

1. 管理员或仓库人员创建出库单。
2. 系统保存出库单和出库明细。
3. 仓库人员执行拣货完成。
4. 仓库人员逐件扫描商品条码、SKU 或二维码内容确认出库数量。
5. 所有明细已扫数量达到计划数量后执行发运。
6. 系统校验可用库存是否充足。
7. 库存充足则扣减库存。
8. 系统释放库位已用容量。
9. 系统记录出库库存流水。
10. 出库单状态变为已发运。

### 3. 扫码作业流程

1. 作业人员在 Web PDA 或安卓手持端登录。
2. 扫描统一作业编码、库位码、SKU 或商品条码。
3. 系统自动识别对象类型。
4. 前端展示对象详情。
5. 作业人员根据对象类型执行收货、上架、取件、拣货、发运、库存查询或盘点操作。
6. 系统同步更新业务单据、库存和流水。

### 4. 盘点业务流程

1. 创建盘点单，选择仓库和货主。
2. 系统根据当前库存生成盘点明细。
3. 仓库人员录入实盘数量。
4. 系统计算差异。
5. 无差异则盘点完成。
6. 有差异则进入待复核状态，并生成异常工单。
7. 复核后执行库存调整。
8. 系统记录盘点调整流水。

### 5. 预警处理流程

1. 系统按固定周期扫描入库、出库、库存和取件数据。
2. 满足规则条件时生成或刷新预警事件。
3. 预警中心展示待处理预警。
4. 管理人员确认预警。
5. 如果业务恢复正常，系统自动将预警标记为已恢复。
6. 取件滞留等场景可自动生成异常工单和短信通知。

### 6. 计费结算流程

1. 创建客户计费合同。
2. 为合同配置计费规则。
3. 选择合同和账单月份生成账单。
4. 系统按入库、出库或库存数据计算计费数量。
5. 系统根据单价生成账单明细和总金额。
6. 财务或管理员确认收款后标记账单已付款。

## 七、系统安全与企业化能力

主要能力：

- `/api/**` 接口统一 token 鉴权。
- 登录 token 使用 HMAC-SHA256 签名并带过期时间。
- 密码使用 PBKDF2 哈希保存。
- 支持历史明文密码自动升级。
- 后端按角色菜单路径进行接口级 RBAC 校验。
- 前端根据用户菜单路径动态显示菜单。
- 接口请求统一注入 Authorization token。
- 统一业务异常处理和统一 API 响应结构。
- 请求自动生成或透传 `X-Request-Id`，便于日志排查。
- CORS、token 密钥、token 过期时间、数据库密码支持环境变量配置。
